# Custom chat renderer for SA-MP Android via mimgui

ChatEngine intercepts SA-MP server and player chat messages through `samp.events` hooks, stores them in a fixed-size ring buffer (200 messages), parses SA-MP `{RRGGBB}` color codes into colored text segments, and renders everything in a custom `mimgui` window with filter tabs, fade-out auto-hide, a minimize state, and a persistent config panel. The architecture splits cleanly: `chatengine_lib.lua` owns the data model (buffer, parsing, categorization) while `ChatEngine.lua` handles all UI rendering, event hooks, and user commands.

**Watch for:** The "IC" filter tab maps to the "Action" category internally, but normal player chat (from `onChatMessage`) is categorized as "Server" — so IC tab shows `/me` actions but not regular player speech (confirmed). The `cfgEnabled` config toggle is read into an imgui bool at startup but never actually consulted at runtime to gate interception (confirmed). Auto-scroll logic tracks `bufferCount` which saturates at 200 and stops triggering new-message detection once the ring buffer wraps (confirmed).

## High-level view

The two-file split is clean: the library module is stateless from the caller's perspective (all state is module-local) and exposes a small surface. The main script consumes it through a single `chatlib` reference, making the library independently testable.

The filter tab design has a semantic gap: the tabs are named "All", "PM", "Server", "IC", "OOC" but the underlying category detector produces "PM", "OOC", "Action", "Ad", "Server". "IC" maps to "Action" via `mapFilterToCategory`, and "Ad" messages have no dedicated tab — they'll appear in "All" but are unreachable individually. Regular player chat lands in "Server" because `onChatMessage` formats a plain string that doesn't match any category pattern, making "IC" a misnomer for what it actually filters.

The auto-hide and fade system tracks last message arrival via `os.clock()` and fades over the final 2 seconds of the delay window. The auto-scroll mechanism will silently break once the buffer fills because it compares against `bufferCount` which stops incrementing at 200.

## Filter-to-category mapping gap

The filter tabs present five options: All, PM, Server, IC, OOC. The category detector produces five categories: PM, OOC, Action, Ad, Server. The mapping function bridges one mismatch (`"IC"` → `"Action"`) but leaves another unaddressed: `"Ad"` has no corresponding tab.

The "IC" label misleads. In SA-MP roleplay terminology, "IC" means in-character speech — the dominant message type in any RP server. But the filter only shows messages starting with `* ` (the `/me` action prefix). Normal player chat arrives through `onChatMessage`, gets formatted as `"PlayerName (ID): text"`, and since that string doesn't start with `* `, it falls through to the default `"Server"` category. A player expecting to isolate IC speech from server announcements will find both mixed in the Server tab.

The fix is either to assign a distinct category to `onChatMessage`-sourced messages (e.g., `"Chat"` or `"IC"`) at insertion time, or to pass category as an explicit parameter to `chatlib.addMessage` so the caller controls classification rather than relying solely on text pattern matching.

## Auto-scroll saturation at buffer capacity

```lua
local currentCount = chatlib.getBufferSize()
if currentCount > lastMessageCount then
    imgui.SetScrollHereY(1.0)
    lastMessageCount = currentCount
end
```

`getBufferSize()` returns `bufferCount`, which increments until it hits `MAX_BUFFER_SIZE` (200) and then stays there permanently. After 200 messages, `currentCount` equals `lastMessageCount` on every frame and auto-scroll never fires. The user would need to manually scroll to see new messages once the buffer is full.

Fix: maintain a monotonically-increasing insertion counter in the library (never reset, never capped) and expose it via a `getInsertionCount()` function. The UI compares against that instead of buffer size.

## cfgEnabled checkbox is decorative

The `cfgEnabled` imgui bool is rendered in the config panel and persisted to the ini file, but the runtime variable that actually controls interception is `chatInterceptEnabled` — a plain Lua boolean set only by the `/ceoff` command. There's no code path that reads `cfgEnabled[0]` to update `chatInterceptEnabled`, and at script startup `chatInterceptEnabled` is hardcoded to `true` regardless of the ini value.

A user who unchecks "Enable ChatEngine" and saves config will see the setting persist in the file but have no observable effect.

## Color integer handling on LuaJIT

MonetLoader typically runs LuaJIT, which uses Lua 5.1 semantics for the `%` operator. In Lua 5.1, the modulo of a negative number follows the sign of the dividend: `-1 % 256 = -1`, not `255`. SA-MP color values with the high bit set (any color with alpha > 127, or R > 127 when alpha is 0) will be represented as negative numbers in Lua's double-precision representation.

For example, `0xFF6633FF` as a signed 32-bit integer is `-10079233`. Decomposing with `color % 256` yields a negative value for the blue channel rather than `255`. The RGB extraction would produce incorrect negative float values passed to `imgui.TextColored`.

The standard fix is to use `bit.band` and `bit.rshift` (available in LuaJIT) for color decomposition, or to add `color = color % (2^32)` at the top to normalize to an unsigned range.

## Category detection fragility

The `detectCategory` function inspects the final formatted string, but for `onChatMessage` the string is constructed as `"PlayerName (ID): text"`. Category detection depends on what the player typed, not on the message source. If a player's message starts with `* ` it would be misclassified as "Action" even though it came through normal chat rather than a server-formatted `/me`.

The risk is low in practice (most RP servers strip leading `*` from regular chat), but the architecture is fragile. Classification should ideally be assigned at the hook level — pass category as a parameter to `chatlib.addMessage` — rather than inferred from formatted text patterns.

## Font size slider has no effect

`cfgFontSize` appears in the config panel with a 10–24 range slider and is persisted to the ini file, but no rendering code references it. The chat window renders at mimgui's default font size regardless of this setting. Either wire it to `imgui.SetWindowFontScale(cfgFontSize[0] / 14.0)` before the chat child window, or remove the slider to avoid confusing users.
